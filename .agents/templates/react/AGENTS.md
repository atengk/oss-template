# React (Next.js App Router) 协作规范与 AI Agent 行为准则

本规范基于全局通用协作基准，针对 **React (Next.js 14/15 App Router + TypeScript + TailwindCSS + Zustand)** 现代全栈技术栈进行了工程特化扩展。下游 React 项目在引入 AI 辅助研发时，须同时遵守第 1~7 章通用基准与第 8 章技术栈特化规约。

---

## 1. 交互与交付规范 (Interaction & Delivery)

- **语言与表达规范 (Language & Localization)**：
  - 需求沟通、技术方案、代码文档注释、工单任务卡片及评审汇报统一使用清晰地道的中文字符；
  - 系统命令、源码标识符（变量名、函数名、类型名）、专有名词、第三方依赖库名称与报错原始堆栈一律保持原始英文，严禁生硬机翻。
- **文件优先交付 (File-First Delivery)**：
  - **落盘门槛**：结构化交付物（架构设计方案、技术调研、API 接口契约、数据结构定义等）及超过 50 行的新建源码，一律优先直接写入项目对应路径的文件中，严禁在交互会话中倾泻长文本；
  - **即时交互豁免**：原理机制解答、排错推演过程等上下文即时交互内容直接在会话中展开；若用户显式要求“在聊天框展示/无需落盘”，则遵循即时指令。
- **会话反馈与链接呈现 (Session Feedback & Links)**：
  - **微片段限额**：会话向用户汇报时仅提炼核心结论与提纲；新建源码仅展示对外导出的核心公共接口摘要（≤ 15 行）；局部修改仅展示核心变更锚点（≤ 15 行），严禁在交互界面刷屏输出大段未裁剪代码；
  - **会话直达链接**：会话向用户汇报文件变更时统一提供 `[文件相对路径/基名](file:///绝对路径)` 点击直达链接；Windows 路径**必须将反斜杠 `\` 转换为正斜杠 `/`**，严禁在会话中暴露裸露的长路径；
  - **交付正文零绝对路径**：严禁将 `file:///` 或包含本地盘符（如 `C:/`、`D:/`）的绝对路径写入任何 Markdown 交付物正文；文档间互链 100% 采用相对路径（`./`、`../`），外部信源采用标准 HTTPS URL。
- **本地验证闭环与测试防作弊 (Pre-delivery Verification & Test Integrity)**：
  - **严禁未经验证宣称完成**：代码新增或修改完成后，必须在本地终端以无头非交互模式运行项目的标准检查命令（如 `npm run lint`、`tsc --noEmit`、`npm test`），验证 100% 成功通过后方可进入交付汇报；
  - **缺陷闭环不甩锅**：若编译报错或测试断言失败，排查与修复是当前任务不可分割的一部分，严禁将未解决的错误直接抛还给用户；
  - **严禁弱化存量测试**：除非当前任务明确声明为既有业务契约的破坏性重构，**严禁为了迎合新代码而私自删除、弱化、注释或断言降级既有存量单元测试**；
  - **真实断言有效性**：新增测试必须覆盖关键业务边界与异常分支，必须包含严谨明确的结果断言，严禁编写无实质断言、纯空跑或滥用全 Mock 糊弄覆盖率的假测试。
- **跨平台一致性与编码标准 (Cross-Platform & Encoding Standards)**：
  - **代码内零硬编码操作系统分隔符**：源码、配置文件与脚本中处理文件路径，一律使用标准正斜杠 `/` 或目标语言标准库提供的路径拼接函数，严禁在代码或字符串拼接中硬编码宿主机反斜杠 `\`；
  - **文本编码与换行符**：新建源码、配置文件、脚本与文档一律采用 UTF-8 编码（无 BOM），换行符统一使用 Unix LF，防止破坏 Linux CI 与容器运行环境。
- **最小影响面原则 (Minimal Blast Radius)**：
  - 代码改动必须严格聚焦于当前指令与目标缺陷；
  - **严禁对无关源码进行大面积重新格式化、缩进重排或无意义的字符变动**，确保版本控制 Diff 干净、清晰、高可读。
- **幂等性与可重入保证 (Idempotency Invariant)**：
  - AI Agent 编写的任何自动化脚本、环境配置逻辑或批量数据流转操作，**必须具备天然的幂等性**（即无论执行 1 次还是连续执行 N 次，系统最终状态完全一致，绝不产生副作用叠加或状态冲突）。

## 2. 代码与文档注释规范 (Code & Comments)

- **顶层架构与文件注释 (Module & File Doc Comments)**：
  - **单一职责陈述**：新建组件源文件必须包含遵循 TSDoc 标准的顶层注释，首段直接清晰陈述该组件或 Hook 的核心职责与架构意图（严禁添加 `职责说明：`、`功能：` 等冗余前缀）；
  - **署名与版本解耦**：代码变更历史、创建者与时间追溯**一律以版本控制系统（Git Commit / Blame）为权威单一信源**；通用基线严禁在文件头强制填充伪作者或时间元数据标签；既有存量文件修改时严格保留原注释。
- **公共契约与行为注释 (Public API Contracts)**：
  - **核心边界说明**：所有对外导出的公共 React 组件、自定义 Hooks（`use*`）及工具函数，必须编写清晰的 TSDoc 契约注释；
  - **信息增量**：重点说明 Props 属性业务约束、默认值、异步加载状态、事件回调触发时机；自解释的私有小组件免除冗余注释。
- **主干流程与编排注释 (Flow & Steps)**：
  - **关键动作编排**：仅在包含 2 个及以上关键动作 (≥ 2) 的复杂交互流转或异步提交编排中，采用提纲化步骤标注（如 `// 1. ...`、`// 2. ...`）；**严禁出现仅有单个孤立步骤号的伪步骤**；
  - **提炼自解释单元**：简单流转或透传逻辑无需步骤标注；复杂逻辑应优先提炼为命名清晰的自定义 Hook，避免超长面条代码。
- **清洁代码红线 (Clean Code)**：
  - **命名即文档**：组件名必须采用大驼峰（`PascalCase`），Hooks 必须以小写 `use` 开头（`camelCase`），样式类优先通过规范排版表达意图，**严禁使用注释为硬编码打补丁**；
  - **意图与防御性说明**：行内注释聚焦说明“为什么这么做”与性能记忆化（Memoization）决策；修改代码时同步修正或清理失效注释；
  - **待办闭环**：严禁随手留空；外部依赖未就绪确需留待办时，统一规范为 `// TODO(<责任人/标识>): <原因与后续动作>`。

## 3. 代码质量与工程健壮性 (Code Quality & Robustness)

- **空安全与前置防御契约 (Null-Safety & Nil Defense)**：
  - **容器查询零空引用**：凡查询或返回一组数据的接口（数组、列表），无匹配数据时**统一返回空数组 `[]`，严禁返回 `null` 或 `undefined`**；
  - **可空标量前置防卫**：任何可能为空的属性读取，必须立即通过可选链（`?.`）与空值合并运算符（`??`）进行安全防卫，杜绝未防御直接访问深层属性导致的运行时白屏。
- **并发安全与无状态设计 (Concurrency & Statelessness)**：
  - **渲染纯函数契约**：React 组件渲染主体必须是无副作用的纯函数；严禁在组件主体执行过程中直接突变外部全局变量；
  - **共享状态受管流转**：跨组件共享的可变状态必须收敛至受管状态中心（如 Zustand Store）；异步请求与数据抓取必须处理竞争条件（Race Conditions）与卸载态竞态拦截。
- **错误与异常处理闭环 (Error & Exception Invariants)**：
  - **零静默吞没**：严禁在异步 Promise 或事件回调中静默忽略错误（空 catch）；所有错误分支必须向用户呈现友好的错误 UI 或降级回退；
  - **组件级错误边界 (Error Boundary)**：UI 树必须配置受管的 `error.tsx`（Next.js）或 ErrorBoundary，防止局部渲染异常导致全页崩溃白屏；
  - **受管日志门面**：**严禁在生产组件中遗留原生 `console.log`**；必须通过统一的日志工具或监控埋点上报。
- **边界解耦与单一职责 (Architectural Decoupling)**：
  - **展示与容器解耦**：UI 表现层组件仅负责渲染与样式，复杂数据加载与业务计算收敛于自定义 Hook 或服务端组件，严禁在视图模板内混入重度计算；
  - **契约模型与持久层隔离**：前端定义的 Props 接口与后端实际落库持久化模型解耦；
  - **杜绝巨石组件**：单个 TSX 文件行数不宜过长，当 JSX 嵌套层级显著增加时必须主动按关注点拆分为轻量小组件。
- **性能底线与资源安全 (Performance & Resource Safety)**：
  - **避免无意义的重渲染**：对于传递给子组件的重型回调与对象，合理利用 `useCallback` 与 `useMemo` 稳定引用；
  - **副作用资源可靠清理**：`useEffect` 中注册的订阅、DOM 监听器或轮询定时器，**必须在 cleanup 回调函数中成对注销**；
  - **依赖克制与锁文件卫生**：严禁私自引入未授权的第三方 npm 包；依赖变更必须维护 `package-lock.json` 或 `pnpm-lock.yaml`。

## 4. Git 提交与版本管理 (Git Conventions)

- **显式两级授权 (Explicit Triggers)**：
  - **本地提交**：仅当用户明确发出“提交/commit/保存变更”指令时方可触发，代码改动默认停留在本地工作区供审阅，严禁自主静默提交；
  - **远程推送**：仅当用户明确发出“推送/push/发布到远端”指令时方可操作。
- **精准路径暂存 (Safe Path Staging)**：
  - 暂存代码必须显式指定目标文件路径（`git add <file-path>`）；**严禁使用 `git add .` 或 `-A` 等通配符一网打尽**。
- **规范化提交 (Conventional Commits)**：
  - **格式约束**：统一遵循 Conventional Commits：`<type>(<scope>): <清晰中文描述>`；
  - **多项改动清单**：单次提交包含多个独立模块或功能点时，在提交正文中分行逐项清晰罗列；
  - **工单闭环标准**：使用符合 RFC 5147 规范的 Git Trailer 关联或闭环工单（如 `Closes #12`、`Refs #14`）；
  - **工程门面优先**：若项目工具链中已提供专门的提交门面脚本，优先通过该脚本进行演练与提交。
- **特性即文档准则 (Doc-as-Feature & Atomic Delivery)**：
  - **原子交付**：新功能开发、对外协议变更与配置改造，必须在同一分支与提交中同步交付对应的测试用例与技术文档；
  - **三板斧验收标准**：
    1. **场景痛点**：一句话阐明解决的业务或工程问题；
    2. **最小用例**：提供复制即用的最小配置、命令或示例代码；
    3. **预期呈现**：明确给出调用输出、响应或预期数据形态。

## 5. 工具链执行策略与安全防护 (Toolchain Strategy & Safeguards)

- **环境优先序 (Environment Precedence)**：工具链优先依赖系统 `PATH` 及项目 `package.json` 所声明的官方工具与版本执行；严禁猜测或执行非标准路径命令。
- **非交互与无阻塞执行 (Non-Interactive & Headless First)**：
  - **静默批处理参数**：执行命令行任务必须显式附加静默、非交互或自动确认参数（如 `-y` 等）；
  - **严禁终端挂起**：严禁执行会挂起等待标准输入（stdin）、键盘按键确认或调用交互式编辑器/分页器的命令；
  - **主动交接阻塞**：若目标命令无法通过参数跳过交互式认证或操作，严禁在后台盲目执行导致挂起；必须主动向用户说明阻塞原因并提供完整命令，引导用户在宿主终端手动执行后继续。
- **破坏性操作熔断红线 (Destructive Action Circuit Breaker)**：
  - **绝对禁止未授权破坏**：严禁在未获得用户明确二次确认的情况下，执行任何不可逆的破坏性命令（包括但不限于 `git reset --hard`、`git clean -f`、强推远端分支、递归清理非临时工作目录、清空持久化存储或无差别强杀系统进程）；
  - **风险前置告警**：遇到确需破坏性重置的场景，必须向用户详尽阐明数据丢失风险，由用户决策并在终端手动执行。

## 6. 信息安全与机密脱敏红线 (Zero-Secret Invariant)

- **零明文不变量 (Zero-Secret Invariant)**：
  - **大写语义占位符**：在任何源码、配置文件、技术文档、脚本及交互会话中，凭据字段统一使用大写语义占位符（如 `YOUR_API_TOKEN`、`user@example.com`）或系统环境变量表达式（如 `${DATABASE_PASSWORD}`、`${API_KEY}`）；
  - **严禁客户端机密泄漏**：在 Next.js 全栈应用中，带私钥或敏感 Token 的环境变量绝对禁止添加 `NEXT_PUBLIC_` 前缀，严禁将私密配置意外打包至客户端前端 JS 制品中。
- **探查资产正向脱敏 (Inspection Sanitization)**：
  - 读取本地运行环境（系统变量、配置文件、本地私有存储）发现真实凭据或内部私网地址时，输出至会话或交付文档前必须强制转译为通用脱敏占位符，严禁原样带出。
- **测试夹具语义化桩豁免 (Mock Exemption)**：
  - 自动化测试与测试夹具中，仅允许使用明显无安全价值的语义化桩数据（如 `test-token`、`dummy-pass`）；严禁在单测中混入真实生产级凭据或有效网络资产。
- **瞬态内存沙箱防护 (Transient Memory Sandbox)**：
  - 用户在会话中主动提供的临时有效凭据，仅限在当前易失性内存中受控调用；会话回复中必须自动掩码（如 `sk-***abcd`）；严禁持久化落盘到任何文件。

## 7. AI 交付前自检清单 (Pre-flight Self-Check Checklist)

在正式向用户宣告交付或提交通知前，AI Agent 必须在会话心智中自检以下项目是否 100% 闭环：

- [ ] **两级授权与安全暂存**：所有代码变更是否在已授权范围？暂存是否显式指定目标文件且彻底杜绝了 `git add .` / `-A`？
- [ ] **本地验证真实闭环**：是否已在本地实际执行过 `npm run lint` 与 `tsc --noEmit` 静态类型检查？
- [ ] **测试真实有效性**：是否 100% 保留且未弱化任何既有存量单测断言？新增测试是否包含严谨有约束力的真实断言（杜绝空跑/假测试）？
- [ ] **并发与状态安全**：组件渲染主体是否保持纯函数？副作用 cleanup 是否均已成对注册注销？
- [ ] **破坏性操作零触发**：是否绝对没有擅自执行任何可能造成本地未暂存代码丢失或历史被覆写的破坏性命令？
- [ ] **跨平台与文件编码**：源码中路径处理是否零硬编码反斜杠 `\`？新建文件是否遵循 UTF-8 无 BOM 与 LF 换行符？
- [ ] **空安全与边界拦截**：列表无数据时是否均返回了空数组？深层可选对象是否通过可选链（`?.`）进行了完整防卫？
- [ ] **错误闭环与日志纯净**：生产代码中是否杜绝了裸 `console.log`？是否配置了 `error.tsx` 错误兜底边界？
- [ ] **机密脱敏 100%**：代码、注释、文档中是否绝对没有硬编码任何真实凭据？服务端私密环境变量是否杜绝了 `NEXT_PUBLIC_` 暴露？
- [ ] **Diff 纯净与零绝对路径**：Git Diff 是否无大面积无关格式化污染？交付 Markdown 正文中是否做到了 100% 相对路径？
- [ ] **React RSC 边界把控**：默认组件是否为 Server Components？`'use client'` 是否仅在必要的交互叶子组件中添加？
- [ ] **React Hooks 依赖真实性**：`useEffect`、`useCallback` 的依赖数组是否完整？是否存在使用 `eslint-disable` 屏蔽检查的逃逸行为？
- [ ] **React 状态不可变契约**：修改 State 时是否 100% 遵守不可变更新（展开运算符/不可变复制）？是否存在直接 push 或字段突变？

## 8. React (Next.js App Router + TypeScript) 特化工程规约

### 8.1 服务端组件 (RSC) 优先架构
- **默认全量 Server Components**：
  - 在 Next.js App Router（`app/` 目录）中，**所有页面（`page.tsx`）、布局（`layout.tsx`）与展示型组件默认均为 Server Components**（无需添加任何前缀指令）；
  - 数据获取优先在服务端组件内直接以 `async/await` 异步调用，享受零客户端打包体积与私密凭据绝对安全的优势；
- **客户端组件下沉原则 (Push Client Components to Leaves)**：
  - 仅在组件确实需要浏览器交互时（如 `useState`、`useEffect`、DOM 监听 `onClick`、浏览器专属 API），才在**文件第一行显式标注 `'use client'`**；
  - **绝对禁止在根布局（`app/layout.tsx`）或顶层大容器组件上盲目标注 `'use client'`**，必须将交互逻辑下沉至具体的叶子节点小组件（如 `<ThemeToggle />`、`<SearchBar />`），保留外层布局的服务端流式渲染。

### 8.2 Hooks 严谨性与闭包防陷阱
- **依赖项数组绝对真实完整**：
  - `useEffect`、`useCallback`、`useMemo` 的依赖数组必须包含在副作用中引用的所有组件作用域变量（Props、State 与函数）；
  - **绝对禁止使用 `// eslint-disable-next-line react-hooks/exhaustive-deps` 暴力屏蔽检查**；
  - 若依赖项频繁变动导致死循环，应通过函数式更新（如 `setCount(prev => prev + 1)`）或将无依赖纯函数移出组件外解决。
- **状态不可变性铁律 (State Immutability)**：
  - **绝对严禁直接突变外部 State 或 Props 属性**（严禁 `state.push(item)` 或 `obj.title = 'new'`）；
  - 必须使用扩展运算符或不可变更新生成全新引用（`[...state, item]`、`{ ...obj, title: 'new' }`），确保 React 准确识别引用变化触发重新渲染。

### 8.3 强类型契约与组件边界
- **组件 Props 强制类型化**：
  - 每个组件必须显式定义 Props 接口或类型别名：
    ```tsx
    interface UserCardProps {
      userId: string;
      displayName: string;
      onSelect?: (userId: string) => void;
      children?: React.ReactNode;
    }

    export function UserCard({ userId, displayName, onSelect, children }: UserCardProps) {
      ...
    }
    ```
  - **全局绝对禁止使用 `any` 标注 Props 或事件类型**；事件对象统一使用 React 标准类型（如 `React.MouseEvent<HTMLButtonElement>`）。

### 8.4 状态管理与样式原子化
- **轻量全局状态 (Zustand)**：
  - 跨组件/跨页面的客户端全局状态推荐使用 **Zustand** 管理，保持极简直观与零模版代码；
  - 严禁在现代 Next.js 项目中引入过时笨重的 Redux 架构；
- **TailwindCSS 原子类与合并工具**：
  - 组件排版优先使用 TailwindCSS 实用类；
  - 条件样式拼接必须通过 `cn(...)` 工具函数（基于 `clsx` 与 `tailwind-merge`）安全合并，避免样式冲突；严禁编写裸行内样式对象（`style={{ ... }}`）。

### 8.5 代差排斥清单 (Forbidden Legacy APIs / Anti-Patterns)
- ❌ **绝对禁止在顶层 Layout 盲目加 `'use client'`**；
- ❌ **绝对禁止使用 `eslint-disable` 屏蔽 `exhaustive-deps` 规则**；
- ❌ **绝对禁止在 TypeScript 中使用 `any`**；
- ❌ **绝对禁止直接突变 State 对象或 Props 属性**；
- ❌ **绝对禁止编写旧式类组件（Class Components，统一使用函数组件与 Hooks）**；
- ❌ **绝对禁止在组件顶层同步渲染逻辑中直接发起 `fetch` 网络请求**（普通客户端组件必须在 `useEffect` 或 React Query 中发起）。
