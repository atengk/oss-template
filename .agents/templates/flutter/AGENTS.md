# Flutter (Dart 3) 协作规范与 AI Agent 行为准则

本规范基于全局通用协作基准，针对 **Flutter (Dart 3 + Flutter 3.x 跨平台移动端/桌面端)** 现代技术栈进行了工程特化扩展。下游 Flutter 项目在引入 AI 辅助研发时，须同时遵守第 1~7 章通用基准与第 8 章技术栈特化规约。

---

## 1. 交互与交付规范 (Interaction & Delivery)

- **语言与表达规范 (Language & Localization)**：
  - 需求沟通、技术方案、代码文档注释、工单任务卡片及评审汇报统一使用清晰地道的中文字符；
  - 系统命令、源码标识符（变量名、函数名、类型名）、专有名词、第三方依赖库名称与报错原始堆栈一律保持原始英文，严禁生硬机翻。
- **文件优先交付 (File-First Delivery)**：
  - **落盘门槛**：结构化交付物（架构设计方案、技术调研、API 接口契约、数据结构定义等）及超过 50 行的新建源码，一律优先直接写入项目对应路径的文件中，严禁在交互会话中倾泻长文本；
  - **即时交互豁免**：原理机制解答、排错推演过程等上下文即时交互内容直接在会话中展开；若用户显式要求“在聊天框展示/无需落盘”，则遵循即时指令。
- **会话反馈与链接呈现 (Session Feedback & Links)**：
  - **微片段限额**：会话向用户汇报时仅提炼核心结论与提纲；新建源码仅展示对外导出的核心公共接口摘要（≤ 15 行）；局部修改仅展示核心变更锚点（≤ 15 行），严禁在交互界面刷屏输出大段未裁剪代码；
  - **会话直达链接**：会话向用户汇报文件变更时统一提供 `[文件相对路径/基名](file:///绝对路径)` 点击直达链接；Windows 路径**必须将反斜杠 `\` 转换为正斜杠 `/`**，严禁在会话中暴露裸露的长路径；
  - **交付正文零绝对路径**：严禁将 `file:///` 或包含本地盘符（如 `C:/`、`D:/`）的绝对路径写入任何 Markdown 交付物正文；文档间互链 100% 采用相对路径（`./`、`../`），外部信源采用标准 HTTPS URL。
- **本地验证闭环与测试防作弊 (Pre-delivery Verification & Test Integrity)**：
  - **严禁未经验证宣称完成**：代码新增或修改完成后，必须在本地终端以无头非交互模式运行项目的标准检查命令（如 `flutter analyze`、`flutter test`），验证 100% 成功通过（零 warning、零 error）后方可进入交付汇报；
  - **缺陷闭环不甩锅**：若编译报错或测试断言失败，排查与修复是当前任务不可分割的一部分，严禁将未解决的错误直接抛还给用户；
  - **严禁弱化存量测试**：除非当前任务明确声明为既有业务契约的破坏性重构，**严禁为了迎合新代码而私自删除、弱化、注释或断言降级既有存量单元测试/组件测试**；
  - **真实断言有效性**：新增测试必须覆盖关键业务边界与异常分支，必须包含严谨明确的结果断言，严禁编写无实质断言、纯空跑或滥用全 Mock 糊弄覆盖率的假测试。
- **跨平台一致性与编码标准 (Cross-Platform & Encoding Standards)**：
  - **代码内零硬编码操作系统分隔符**：源码、配置文件与脚本中处理文件路径，一律使用标准正斜杠 `/` 或目标语言标准库提供的路径抽象（如 `path` package），严禁在代码或字符串拼接中硬编码宿主机反斜杠 `\`；
  - **文本编码与换行符**：新建源码、配置文件、脚本与文档一律采用 UTF-8 编码（无 BOM），换行符统一使用 Unix LF，防止破坏 Linux CI 与容器运行环境。
- **最小影响面原则 (Minimal Blast Radius)**：
  - 代码改动必须严格聚焦于当前指令与目标缺陷；
  - **严禁对无关源码进行大面积重新格式化、缩进重排或无意义的字符变动**，确保版本控制 Diff 干净、清晰、高可读。
- **幂等性与可重入保证 (Idempotency Invariant)**：
  - AI Agent 编写的任何自动化脚本、环境配置逻辑或批量数据流转操作，**必须具备天然的幂等性**（即无论执行 1 次还是连续执行 N 次，系统最终状态完全一致，绝不产生副作用叠加或状态冲突）。

## 2. 代码与文档注释规范 (Code & Comments)

- **顶层架构与文件注释 (Module & File Doc Comments)**：
  - **单一职责陈述**：新建源文件必须包含遵循 Dartdoc 规范的顶层文档注释（`///`），首段直接清晰陈述该组件、数据模型或服务类的核心职责与架构意图（严禁添加 `职责说明：`、`功能：` 等冗余前缀）；
  - **署名与版本解耦**：代码变更历史、创建者与时间追溯**一律以版本控制系统（Git Commit / Blame）为权威单一信源**；通用基线严禁在文件头强制填充伪作者或时间元数据标签；既有存量文件修改时严格保留原注释。
- **公共契约与行为注释 (Public API Contracts)**：
  - **核心边界说明**：所有对外导出的公共类、公共方法、构造函数及公开属性，必须编写以 `///` 开头的契约注释；
  - **信息增量**：重点说明 Widget 入参属性约束、事件回调触发时机、可能抛出的异常类（`@throws`）；自解释的私有辅助方法免除冗余注释。
- **主干流程与编排注释 (Flow & Steps)**：
  - **关键动作编排**：仅在包含 2 个及以上关键动作 (≥ 2) 的复杂异步请求流转或状态编排中，采用提纲化步骤标注（如 `// 1. ...`、`// 2. ...`）；**严禁出现仅有单个孤立步骤号的伪步骤**；
  - **提炼自解释单元**：简单流转或透传逻辑无需步骤标注；复杂逻辑应优先提炼为命名清晰的私有辅助函数或独立组件，避免超长面条代码。
- **清洁代码红线 (Clean Code)**：
  - **命名即文档**：类名与类型名必须采用大驼峰（`UpperCamelCase`），变量与函数采用小驼峰（`lowerCamelCase`），文件与目录采用下划线蛇形（`snake_case.dart`）；
  - **意图与防御性说明**：行内注释聚焦说明“为什么这么做”与平台兼容性防御；修改代码时同步修正或清理失效注释；
  - **待办闭环**：严禁随手留空；外部依赖未就绪确需留待办时，统一规范为 `// TODO(<责任人/标识>): <原因与后续动作>`。

## 3. 代码质量与工程健壮性 (Code Quality & Robustness)

- **空安全与前置防御契约 (Null-Safety & Nil Defense)**：
  - **容器查询零空引用**：凡查询或返回一组数据的接口（列表、集合、字典），无匹配数据时**统一返回对应类型的空集合（`[]`、`{}`），严禁返回 null**；
  - **零强行空断言操作符 `!`**：任何可能为 null 的变量，在访问其属性或方法前，**必须通过前置卫语句判空（`if (user != null)`）或安全调用操作符（`?.`、`??`）进行安全防卫**，绝对严禁使用 `!` 强行解包导致运行时崩溃。
- **并发安全与无状态设计 (Concurrency & Statelessness)**：
  - **组件渲染纯函数化**：Widget 的 `build` 方法必须是无副作用的纯计算过程，**绝对严禁在 `build` 方法内部发起异步网络请求、写入数据库或修改状态**；
  - **异步竞态安全**：多次快速点击触发的异步事件必须通过去抖（Debounce）或状态互斥锁防止重复提交。
- **错误与异常处理闭环 (Error & Exception Invariants)**：
  - **零静默吞没**：严禁在 `try-catch` 中编写空 `catch` 块；所有异常必须向用户显示错误提示（如 SnackBar/Dialog）或记录日志；
  - **杜绝日志风暴**：遵循“**要么本地降级并受管记录，要么转化为上层可理解的业务异常向外抛出**”原则；
  - **受管日志门面**：**严禁在正式代码中使用原始标准输出（裸 `print()`）**；统一使用受管日志库或 `debugPrint` / `log` 进行结构化分级输出。
- **边界解耦与单一职责 (Architectural Decoupling)**：
  - **视图与业务解耦**：UI Widget 仅负责视图呈现与用户交互绑定，业务逻辑与数据流转必须封装在 State Notifier / BLoC / Repository 中，**严禁在 Widget 内部堆砌冗长的业务与网络处理代码**；
  - **数据传输与持久化解耦**：API 传输模型与本地数据库实体解耦分离；
  - **杜绝巨石组件**：单个 Widget 类代码行数不宜过长，复杂视图必须按业务语义拆分为独立的子 Widget。
- **性能底线与资源安全 (Performance & Resource Safety)**：
  - **杜绝批量低效操作**：长列表视图必须使用懒加载虚拟列表（`ListView.builder`、`GridView.builder`），绝对严禁直接使用全量初始化的 `ListView(children: ...)`；
  - **生命周期资源必须释放**：所有控制器（Controller）、动画计时器（AnimationController）、Stream 订阅，必须在 `dispose` 时可靠注销；
  - **依赖克制与锁文件卫生**：严禁私自引入未经验证的第三方 pub 包；依赖调整必须严格维护 `pubspec.lock`。

## 4. Git 提交与版本管理 (Git Conventions)

- **显式两级授权 (Explicit Triggers)**：
  - **本地提交**：仅当用户明确发出“提交/commit/保存变更”指令时方可触发，代码改动默认停留在本地工作区供审阅，严禁自主静默提交；
  - **远程推送**：仅当用户明确发出“推送/push/发布到远端”指令时方可操作。
- **精准路径暂存 (Safe Path Staging)**：
  - 暂存代码必须显式指定目标文件路径（`git add <file-path>`）；**严禁使用 `git add .` 或 `-A` 等通配符一网打尽**。
- **规范化提交 (Conventional Commits)**：
  - **格式约束**：统一遵循 Conventional Commits：`<type>(<scope>): <清晰中文描述>`；
  - **多项改动清单**：单次提交包含多个独立模块或功能点时，在提交正文中分行逐项清晰罗列；
  - **工单闭环标准**：使用符合 RFC 5147 规范的 Git Trailer 关联或闭环工单（如 `Closes #12`、`Refs #14`）；
  - **工程门面优先**：若项目工具链中已提供专门的提交门面脚本，优先通过该脚本进行演练与提交。
- **特性即文档准则 (Doc-as-Feature & Atomic Delivery)**：
  - **原子交付**：新功能开发、对外协议变更与配置改造，必须在同一分支与提交中同步交付对应的测试用例与技术文档；
  - **三板斧验收标准**：
    1. **场景痛点**：一句话阐明解决的业务或工程问题；
    2. **最小用例**：提供复制即用的最小配置、命令或示例代码；
    3. **预期呈现**：明确给出调用输出、响应或预期数据形态。

## 5. 工具链执行策略与安全防护 (Toolchain Strategy & Safeguards)

- **环境优先序 (Environment Precedence)**：工具链优先依赖系统 `PATH` 及项目 `pubspec.yaml` 所声明的官方 Flutter/Dart SDK 执行；严禁猜测或执行非标准路径命令。
- **非交互与无阻塞执行 (Non-Interactive & Headless First)**：
  - **静默批处理参数**：执行命令行任务必须显式附加静默、非交互或自动确认参数；
  - **严禁终端挂起**：严禁执行会挂起等待标准输入（stdin）、键盘按键确认或调用交互式编辑器/分页器的命令；
  - **主动交接阻塞**：若目标命令无法通过参数跳过交互式认证或操作，严禁在后台盲目执行导致挂起；必须主动向用户说明阻塞原因并提供完整命令，引导用户在宿主终端手动执行后继续。
- **破坏性操作熔断红线 (Destructive Action Circuit Breaker)**：
  - **绝对禁止未授权破坏**：严禁在未获得用户明确二次确认的情况下，执行任何不可逆的破坏性命令（包括但不限于 `git reset --hard`、`git clean -f`、强推远端分支、递归清理非临时工作目录、清空持久化存储或无差别强杀系统进程）；
  - **风险前置告警**：遇到确需破坏性重置的场景，必须向用户详尽阐明数据丢失风险，由用户决策并在终端手动执行。

## 6. 信息安全与机密脱敏红线 (Zero-Secret Invariant)

- **零明文不变量 (Zero-Secret Invariant)**：
  - **大写语义占位符**：在任何源码、配置文件、技术文档、脚本及交互会话中，凭据字段统一使用大写语义占位符（如 `YOUR_API_TOKEN`、`user@example.com`）或系统环境变量表达式；
  - **严禁客户端敏感硬编码**：移动端打包装箱后极易被逆向反编译，私钥、数据库直连密码与高权限 Token **绝对禁止硬编码在 Flutter 客户端源码中**；敏感配置通过后端网关代理或构建期环境变量注入。
- **探查资产正向脱敏 (Inspection Sanitization)**：
  - 读取本地运行环境（系统变量、配置文件、本地私有存储）发现真实凭据或内部私网地址时，输出至会话或交付文档前必须强制转译为通用脱敏占位符，严禁原样带出。
- **测试夹具语义化桩豁免 (Mock Exemption)**：
  - 自动化测试与测试夹具中，仅允许使用明显无安全价值的语义化桩数据（如 `test-token`、`dummy-pass`）；严禁在单测中混入真实生产级凭据或有效网络资产。
- **瞬态内存沙箱防护 (Transient Memory Sandbox)**：
  - 用户在会话中主动提供的临时有效凭据，仅限在当前易失性内存中受控调用；会话回复中必须自动掩码（如 `sk-***abcd`）；严禁持久化落盘到任何文件。

## 7. AI 交付前自检清单 (Pre-flight Self-Check Checklist)

在正式向用户宣告交付或提交通知前，AI Agent 必须在会话心智中自检以下项目是否 100% 闭环：

- [ ] **两级授权与安全暂存**：所有代码变更是否在已授权范围？暂存是否显式指定目标文件且彻底杜绝了 `git add .` / `-A`？
- [ ] **本地验证真实闭环**：是否已在本地实际执行过 `flutter analyze` 且零警告、零错误？是否通过了 `flutter test`？
- [ ] **测试真实有效性**：是否 100% 保留且未弱化任何既有存量单测断言？新增测试是否包含严谨有约束力的真实断言（杜绝空跑/假测试）？
- [ ] **并发与状态安全**：Widget 的 `build` 方法是否保持纯函数？异步事件是否处理了重复点击与竞态防卫？
- [ ] **破坏性操作零触发**：是否绝对没有擅自执行任何可能造成本地未暂存代码丢失或历史被覆写的破坏性命令？
- [ ] **跨平台与文件编码**：源码中路径处理是否零硬编码反斜杠 `\`？新建文件是否遵循 UTF-8 无 BOM 与 LF 换行符？
- [ ] **空安全与边界拦截**：集合无数据时是否均返回了空容器？是否 100% 杜绝了 `!` 强行空断言操作符？
- [ ] **错误闭环与日志纯净**：生产代码中是否杜绝了裸 `print()` 调试语句？异常是否均有语义化捕获与用户提示？
- [ ] **机密脱敏 100%**：客户端代码、常量与资源文件中是否绝对没有硬编码任何真实服务端私钥或高权限凭据？
- [ ] **Diff 纯净与零绝对路径**：Git Diff 是否无大面积无关格式化污染？交付 Markdown 正文中是否做到了 100% 相对路径？
- [ ] **Flutter 异步裂隙守卫**：所有在 `await` 之后访问 `context`（路由跳转/弹窗/SnackBar）的逻辑，是否均有 `if (!context.mounted) return;` 拦截？
- [ ] **Flutter 资源生命周期释放**：State 中创建的控制器（`TextEditingController`/`AnimationController`）与 Stream 是否均在 `dispose()` 中成对注销并调用 `super.dispose()`？
- [ ] **Flutter 渲染架构优化**：常量 Widget 构造是否均显式标记了 `const`？复杂模块是否均抽取为了独立 `StatelessWidget` 类（杜绝 `Widget _buildItem()` 私有方法）？

## 8. Flutter (Dart 3 + Flutter 3.x) 特化工程规约

### 8.1 异步裂隙防线与生命周期卫生 (Async Gaps & Dispose)
- **`BuildContext` 跨异步裂隙必须前置守卫**：
  - 在任何异步 `await` 调用之后，如果需要访问 `BuildContext`（如执行 `Navigator.pop(context)`、`ScaffoldMessenger.of(context).showSnackBar()`、`Theme.of(context)` 等）；
  - **必须强制通过 `if (!context.mounted) return;`（在 State 内使用 `if (!mounted) return;`）做前置拦截卫语句**：
    ```dart
    // 正确范式：await 之后必须做 mounted 防卫
    Future<void> submitOrder(BuildContext context) async {
      await orderService.submit();
      if (!context.mounted) return;
      Navigator.of(context).pop();
    }
    ```
  - **绝对禁止未做防卫直接跨 `await` 访问 context**，防止由于页面提前失活退出导致致命未捕获异常。
- **控制器与监听订阅成对注销 (Resource Cleanup)**：
  - 凡在 `State` 中初始化的 `TextEditingController`、`ScrollController`、`AnimationController`、`FocusNode` 及 `StreamSubscription`；
  - **必须在 `dispose()` 回调方法中显式调用其 `.dispose()` 或 `.cancel()`**，且必须在末尾调用 `super.dispose()`，杜绝客户端内存泄漏。

### 8.2 组件树渲染优化与组件拆分原则
- **全面强制使用 `const` 构造函数**：
  - 凡入参固定、不依赖运行时动态可变内部状态的 Widget 实例化，**必须显式加上 `const` 关键字**（如 `const SizedBox(height: 16)`、`const Text('确定')`）；
  - 使得 Flutter 渲染管线能够直接复用 Element 节点，跳过冗余的重新构建。
- **Widget 独立类拆解原则（杜绝私有辅助方法）**：
  - 当视图结构变复杂时，**必须将子模块抽取为独立的 `StatelessWidget` 类**；
  - **绝对严禁在类内部抽取为返回 Widget 的私有方法（如 `Widget _buildOrderItem()`）**；
  - 原因：私有辅助方法不会在 Element 树中生成独立节点，父级重建会导致私有方法内部无条件全量重跑，无法享受常量缓存与局部脏标记定向重绘。
- **`build()` 方法保持轻量纯计算**：
  - 严禁在 `build()` 方法中初始化控制器、发起异步网络请求或执行耗时密集计算。

### 8.3 架构分层与受管状态流 (State Management)
- **严格遵循单向数据流架构**：
  - 页面结构遵循 `UI View` -> `State/Notifier` -> `Repository/Service` -> `DataSource` 规范分层；
  - 推荐采用现代受管状态管理方案：**Riverpod (v2+)** 或 **BLoC / Cubit**；
  - **绝对禁止在大型复杂页面中跨多层透传 `setState` 回调**；
  - **绝对禁止使用破坏上下文、绕过 Flutter 标准 Widget 树生命周期的非受管全局单例状态工具（如 `GetX` 裸单例模式）**，确保代码具备可测试性与生命周期可控性。

### 8.4 Dart 3 严格空安全与现代范式
- **彻底消灭感叹号 `!` 强行空断言**：
  - **在生产代码中绝对禁止使用 `!` 强行断言非空**（如 `user!.name`）；
  - 必须使用卫语句提升为非空类型（`if (user == null) return;` 之后局部变量自动智能类型收缩为非空），或使用 `?.` 与 `??` 提供安全回退；
- **全面启用 Dart 3 模式匹配与密封类**：
  - 领域状态机必须采用 `sealed class` 声明状态基类（如 `sealed class OrderState {}`）；
  - 在 UI 渲染中使用 Dart 3 `switch` 表达式根据状态映射界面，享受编译期**穷尽性检查（Exhaustiveness Checking）**，防止漏写状态分支：
    ```dart
    Widget buildStateView(OrderState state) => switch (state) {
      OrderInitial() => const LoadingSpinner(),
      OrderLoaded(:final data) => OrderDetailView(order: data),
      OrderError(:final message) => ErrorNotice(message: message),
    };
    ```
- **多返回值优先使用原生 Records**：
  - 跨函数传递临时组合数据直接使用 Dart 3 Records `(String, int)`，禁止为临时代数积创建冗余实体类。

### 8.5 代差排斥清单 (Forbidden Legacy APIs / Anti-Patterns)
- ❌ **绝对禁止在 `await` 之后未经 `!context.mounted` 防卫直接使用 `BuildContext`**；
- ❌ **绝对禁止在生产代码中使用 `!` 强制解包可空引用**；
- ❌ **绝对禁止在 State 中遗漏 Controller 的 `dispose()` 注销**；
- ❌ **绝对禁止使用 `Widget _buildItem()` 私有辅助函数拆解子树**（统一抽取独立 `StatelessWidget`）；
- ❌ **绝对禁止在 `build()` 方法体内发起网络请求或实例化 Controller**；
- ❌ **绝对禁止在生产代码中使用裸 `print()` 输出日志**。
