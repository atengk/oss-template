# Java (Spring Boot 3) 协作规范与 AI Agent 行为准则

本规范基于全局通用协作基准，针对 **Java (Spring Boot 3.x + JDK 17/21)** 技术栈进行了工程特化扩展。下游 Java 项目在引入 AI 辅助研发时，须同时遵守第 1~7 章通用基准与第 8 章技术栈特化规约。

---

## 1. 交互与交付规范 (Interaction & Delivery)

- **语言与表达规范 (Language & Localization)**：
  - 需求沟通、技术方案、代码文档注释、工单任务卡片及评审汇报统一使用清晰地道的中文字符；
  - 系统命令、源码标识符（变量名、函数名、类型名）、专有名词、第三方依赖库名称与报错原始堆栈一律保持原始英文，严禁生硬机翻。
- **文件优先交付 (File-First Delivery)**：
  - **落盘门槛**：结构化交付物（架构设计方案、技术调研、API 接口契约、数据结构定义等）及超过 50 行的新建源码，一律优先直接写入项目对应路径的文件中，严禁在交互会话中倾泻长文本；
  - **即时交互豁免**：原理机制解答、排错推演过程等上下文即时交互内容直接在会话中展开；若用户显式要求“在聊天框展示/无需落盘”，则遵循即时指令。
- **会话反馈与链接呈现 (Session Feedback & Links)**：
  - **微片段限额**：会话向用户汇报时仅提炼核心结论与提纲；新建源码仅展示对外导出的核心公共接口摘要（≤ 15 行）；局部修改仅展示核心变更锚点（≤ 15 行），严禁在交互界面刷屏输出大段未裁剪代码；
  - **会话直达链接**：会话向用户汇报文件变更时统一提供 `[文件相对路径/基名](file:///绝对路径)` 点击直达链接；Windows 路径**必须将反斜杠 `\` 转换为正斜杠 `/`**，严禁在会话中暴露裸露的长路径；
  - **交付正文零绝对路径**：严禁将 `file:///` 或包含本地盘符（如 `C:/`、`D:/`）的绝对路径写入任何 Markdown 交付物正文；文档间互链 100% 采用相对路径（`./`、`../`），外部信源采用标准 HTTPS URL。
- **本地验证闭环与测试防作弊 (Pre-delivery Verification & Test Integrity)**：
  - **严禁未经验证宣称完成**：代码新增或修改完成后，必须在本地终端以无头非交互模式运行项目的标准检查命令（如类型检查、编译构建或测试套件），验证 100% 成功通过后方可进入交付汇报；
  - **缺陷闭环不甩锅**：若编译报错或测试断言失败，排查与修复是当前任务不可分割的一部分，严禁将未解决的错误直接抛还给用户；
  - **严禁弱化存量测试**：除非当前任务明确声明为既有业务契约的破坏性重构，**严禁为了迎合新代码而私自删除、弱化、注释或断言降级既有存量单元测试**；
  - **真实断言有效性**：新增测试必须覆盖关键业务边界与异常分支，必须包含严谨明确的结果断言，严禁编写无实质断言、纯空跑或滥用全 Mock 糊弄覆盖率的假测试。
- **跨平台一致性与编码标准 (Cross-Platform & Encoding Standards)**：
  - **代码内零硬编码操作系统分隔符**：源码、配置文件与脚本中处理文件路径，一律使用标准正斜杠 `/` 或目标语言标准库提供的路径拼接函数，严禁在代码或字符串拼接中硬编码宿主机反斜杠 `\`；
  - **文本编码与换行符**：新建源码、配置文件、脚本与文档一律采用 UTF-8 编码（无 BOM），换行符统一使用 Unix LF，防止破坏 Linux CI 与容器运行环境。
- **最小影响面原则 (Minimal Blast Radius)**：
  - 代码改动必须严格聚焦于当前指令与目标缺陷；
  - **严禁对无关源码进行大面积重新格式化、缩进重排或无意义的字符变动**，确保版本控制 Diff 干净、清晰、高可读。
- **幂等性与可重入保证 (Idempotency Invariant)**：
  - AI Agent 编写的任何自动化脚本、环境配置逻辑或批量数据流转操作，**必须具备天然的幂等性**（即无论执行 1 次还是连续执行 N 次，系统最终状态完全一致，绝不产生副作用叠加或状态冲突）。

## 2. 代码与文档注释规范 (Code & Comments)

- **顶层架构与文件注释 (Module & File Doc Comments)**：
  - **单一职责陈述**：新建源文件必须包含遵循目标语言官方标准（如 Go Doc、Rustdoc、Python Docstring、Javadoc、TSDoc 等）的顶层文档注释，首段直接清晰陈述该模块的核心职责与架构意图（严禁添加 `职责说明：`、`功能：` 等冗余前缀）；
  - **署名与版本解耦**：代码变更历史、创建者与时间追溯**一律以版本控制系统（Git Commit / Blame）为权威单一信源**；通用基线严禁在文件头强制填充伪作者或时间元数据标签；既有存量文件修改时严格保留原注释。
- **公共契约与行为注释 (Public API Contracts)**：
  - **核心边界说明**：所有对外导出的公共接口、核心领域服务方法及关键数据结构字段，必须编写清晰的契约文档；
  - **信息增量**：重点说明调用前置条件、业务边界约束、入参空值行为、返回值语义以及可能触发的错误/失败场景；自解释的私有小函数或标准框架约定的覆写方法免除冗余注释。
- **主干流程与编排注释 (Flow & Steps)**：
  - **关键动作编排**：仅在包含 2 个及以上关键动作 (≥ 2) 的复杂业务流程编排中，采用提纲化步骤标注（如 `// 1. ...`、`// 2. ...`）；**严禁出现仅有单个孤立步骤号的伪步骤**；
  - **提炼自解释单元**：简单流转或透传逻辑无需步骤标注；复杂逻辑应优先提炼为命名清晰的私有辅助函数，避免超长面条代码。
- **清洁代码红线 (Clean Code)**：
  - **命名即文档**：优先通过严谨自解释的命名与常量/枚举表达语义，**严禁使用注释为硬编码或魔法值打补丁**；
  - **意图与防御性说明**：行内注释聚焦说明“为什么这么做”与防御性决策（如并发隔离、幂等保证、容错退避）；修改代码时同步修正或清理失效注释；
  - **待办闭环**：严禁随手留空；外部依赖未就绪确需留待办时，统一规范为 `// TODO(<责任人/标识>): <原因与后续动作>`。

## 3. 代码质量与工程健壮性 (Code Quality & Robustness)

- **空安全与前置防御契约 (Null-Safety & Nil Defense)**：
  - **容器查询零空引用**：凡查询或返回一组数据的接口（列表、集合、字典、映射、切片），无匹配数据时**统一返回对应类型的空容器，严禁返回空引用/未初始化指针**；
  - **可空标量前置防卫**：任何可能缺失或为空的单一对象引用，在调用其成员、属性、方法或索引前，**必须立即通过前置卫语句（Guard Clauses）显式拦截或判空**，严禁在未作防卫的情况下直接解引用导致运行时崩溃。
- **并发安全与无状态设计 (Concurrency & Statelessness)**：
  - **公共服务保持无状态**：公共单例服务、处理器与全局组件不得持有与特定请求/调用绑定的可变业务状态；
  - **共享可变状态受管与同步**：严禁随意使用未加同步原语（如互斥锁、原子操作、并发安全容器、不可变只读封装）的全局可变状态；多并发访问共享资源必须保证线程/协程/异步安全，彻底杜绝数据竞态（Data Race）。
- **错误与异常处理闭环 (Error & Exception Invariants)**：
  - **零静默吞没**：严禁忽略或吞没任何错误与异常（如空 catch、忽略错误返回值、空 except）；所有错误分支必须有明确的降级补偿或语义化向上传递；
  - **杜绝日志风暴**：遵循“**要么本地降级并受管记录，要么转化为上层可理解的错误抛出/返回**”原则；严禁在同一错误处理分支中既打印全量堆栈又原样向上抛出，避免多层重复日志污染；
  - **受管日志门面**：**严禁在生产源码中使用原始标准输出（裸打印语句）**；必须通过工程配置的受管日志组件进行分级、结构化输出；严禁在交付代码中遗留调试桩。
- **边界解耦与单一职责 (Architectural Decoupling)**：
  - **协议接入层薄层**：负责外部输入（如网络请求、CLI 命令行参数、事件监听、UI 输入）的接入层只负责参数校验、协议转换与服务调度，**严禁堆积重度领域逻辑，严禁越级穿透直接操作底层私有存储**；
  - **协议接口与内部模型隔离**：对外开放的通信契约不得随意与底层私有持久化模型或存储实体混用，必须进行必要的模型解耦；
  - **杜绝巨石文件**：单个源文件必须保持高内聚与单一关注点，严禁编写大而全的超级模块；维护存量大型文件时严格服从增量外拆原则，新增复杂逻辑独立建模块并在原文件做轻量引用。
- **性能底线与资源安全 (Performance & Resource Safety)**：
  - **杜绝批量低效操作**：严禁在循环体内频繁发起独立的 I/O 读取、数据库查询或外部网络请求；批量操作必须采用批量接口；
  - **资源可靠释放**：涉及文件句柄、网络套接字、数据库连接等系统资源的申请，必须使用语言标准机制（如 defer、try-with-resources、RAII、上下文管理器等）确保在任何异常路径下都能可靠释放；
  - **依赖克制与锁文件卫生**：严禁未经确认私自引入外部第三方依赖；调整或新增依赖必须维护项目官方锁文件（Lockfiles），严禁破坏确定性构建环境。

## 4. Git 提交与版本管理 (Git Conventions)

- **显式两级授权 (Explicit Triggers)**：
  - **本地提交**：仅当用户明确发出“提交/commit/保存变更”指令时方可触发，代码改动默认停留在本地工作区供审阅，严禁自主静默提交；
  - **远程推送**：仅当用户明确发出“推送/push/发布到远端”指令时方可操作。
- **精准路径暂存 (Safe Path Staging)**：
  - 暂存代码必须显式指定目标文件路径（`git add <file-path>`）；**严禁使用 `git add .` 或 `-A` 等通配符一网打尽**。
- **规范化提交 (Conventional Commits)**：
  - **格式约束**：统一遵循 Conventional Commits：`<type>(<scope>): <清晰中文描述>`；
  - **多项改动清单**：单次提交包含多个独立模块或功能点时，在提交正文中分行逐项清晰罗列；
  - **工单闭环标准**：使用符合 RFC 5147 规范的 Git Trailer 关联或闭环工单（如 `Closes #12`、`Refs #14`）；
  - **工程门面优先**：若项目工具链中已提供专门的提交门面脚本，优先通过该脚本进行演练与提交。
- **特性即文档准则 (Doc-as-Feature & Atomic Delivery)**：
  - **原子交付**：新功能开发、对外协议变更与配置改造，必须在同一分支与提交中同步交付对应的测试用例与技术文档；
  - **三板斧验收标准**：
    1. **场景痛点**：一句话阐明解决的业务或工程问题；
    2. **最小用例**：提供复制即用的最小配置、命令或示例代码；
    3. **预期呈现**：明确给出调用输出、响应或预期数据形态。

## 5. 工具链执行策略与安全防护 (Toolchain Strategy & Safeguards)

- **环境优先序 (Environment Precedence)**：工具链优先依赖系统 `PATH` 及项目配置文件所声明的官方工具与版本执行；严禁猜测或执行非标准路径命令。
- **非交互与无阻塞执行 (Non-Interactive & Headless First)**：
  - **静默批处理参数**：执行命令行任务必须显式附加静默、非交互或自动确认参数（如 `-y`、`--batch-mode`、`-m` 等）；
  - **严禁终端挂起**：严禁执行会挂起等待标准输入（stdin）、键盘按键确认或调用交互式编辑器/分页器的命令；
  - **主动交接阻塞**：若目标命令无法通过参数跳过交互式认证或操作，严禁在后台盲目执行导致挂起；必须主动向用户说明阻塞原因并提供完整命令，引导用户在宿主终端手动执行后继续。
- **破坏性操作熔断红线 (Destructive Action Circuit Breaker)**：
  - **绝对禁止未授权破坏**：严禁在未获得用户明确二次确认的情况下，执行任何不可逆的破坏性命令（包括但不限于 `git reset --hard`、`git clean -f`、强推远端分支、递归清理非临时工作目录、清空持久化存储或无差别强杀系统进程）；
  - **风险前置告警**：遇到确需破坏性重置的场景，必须向用户详尽阐明数据丢失风险，由用户决策并在终端手动执行。

## 6. 信息安全与机密脱敏红线 (Zero-Secret Invariant)

- **零明文不变量 (Zero-Secret Invariant)**：
  - **大写语义占位符**：在任何源码、配置文件、技术文档、脚本及交互会话中，凭据字段统一使用大写语义占位符（如 `YOUR_API_TOKEN`、`user@example.com`）或系统环境变量表达式（如 `${DATABASE_PASSWORD}`、`${API_KEY}`）；
  - **严禁任何形式的机密硬编码**：涵盖数据库账号密码、公有云/第三方平台密钥（Access Key/Secret）、鉴权令牌（Token/JWT）、私钥证书（RSA/SSH）及个人隐私敏感数据。
- **探查资产正向脱敏 (Inspection Sanitization)**：
  - 读取本地运行环境（系统变量、配置文件、本地私有存储）发现真实凭据或内部私网地址时，输出至会话或交付文档前必须强制转译为通用脱敏占位符，严禁原样带出。
- **测试夹具语义化桩豁免 (Mock Exemption)**：
  - 自动化测试与测试夹具中，仅允许使用明显无安全价值的语义化桩数据（如 `test-token`、`dummy-pass`）；严禁在单测中混入真实生产级凭据或有效网络资产。
- **瞬态内存沙箱防护 (Transient Memory Sandbox)**：
  - 用户在会话中主动提供的临时有效凭据，仅限在当前易失性内存中受控调用；会话回复中必须自动掩码（如 `sk-***abcd`）；严禁持久化落盘到任何文件。

## 7. AI 交付前自检清单 (Pre-flight Self-Check Checklist)

在正式向用户宣告交付或提交通知前，AI Agent 必须在会话心智中自检以下项目是否 100% 闭环：

- [ ] **两级授权与安全暂存**：所有代码变更是否在已授权范围？暂存是否显式指定目标文件且彻底杜绝了 `git add .` / `-A`？
- [ ] **本地验证真实闭环**：是否已在本地实际执行过编译构建/测试/类型检查并确认全部通过？是否存在未经验证的猜测代码？
- [ ] **测试真实有效性**：是否 100% 保留且未弱化任何既有存量单测断言？新增测试是否包含严谨有约束力的真实断言（杜绝空跑/假测试）？
- [ ] **并发与状态安全**：公共服务是否保持无状态？全局或共享可变状态是否已通过同步原语提供完整线程/协程安全保护？
- [ ] **破坏性操作零触发**：是否绝对没有擅自执行任何可能造成本地未暂存代码丢失或历史被覆写的破坏性命令？
- [ ] **跨平台与文件编码**：源码中路径处理是否零硬编码反斜杠 `\`？新建文件是否遵循 UTF-8 无 BOM 与 LF 换行符？
- [ ] **空安全与边界拦截**：容器类结果无匹配时是否均返回了空容器？可能为空的单对象在解引用前是否均有前置卫语句？
- [ ] **错误闭环与日志纯净**：是否存在任何空 catch / 忽略错误的隐患？是否排除了裸打印调试语句并杜绝了重复堆栈日志风暴？
- [ ] **机密脱敏 100%**：代码、注释、文档与测试中是否绝对没有硬编码任何真实凭据？所有敏感字段是否均使用大写语义占位符？
- [ ] **Diff 纯净与零绝对路径**：Git Diff 是否无大面积无关格式化污染？交付 Markdown 正文中是否做到了 100% 相对路径？
- [ ] **Java 构造器注入**：是否 100% 杜绝了 `@Autowired` 字段注入，统一使用 Lombok `@RequiredArgsConstructor private final ...` 构造器注入？
- [ ] **Java 模型边界隔离**：持久层 `*PO` / `*Entity` 是否绝对未作为 Controller 出入参外露？是否通过 `*DTO` / `*VO` 严格隔离？
- [ ] **Java 现代 API 与命名空间**：是否彻底排除了 `javax.*` 废弃包（统一使用 `jakarta.*`）？时间类型是否全量采用 `java.time.*`？

## 8. Java (Spring Boot 3 + JDK 17/21) 特化工程规约

### 8.1 依赖注入与组件设计
- **强制构造器注入**：
  - 统一采用 Lombok 的 `@RequiredArgsConstructor` 注解注入 `private final` 依赖字段；
  - **绝对禁止使用 `@Autowired` 私有字段注入**，防止隐藏循环依赖并在单测中无法解耦实例化。
- **单例服务无状态**：
  - 所有 `@Service`、`@Component`、`@RestController` 必须保持无状态；
  - 严禁在单例类中定义非 `final` 的业务可变成员变量（如计数器、可变集合、当前请求上下文）；请求级上下文必须通过方法参数或受管的 `ThreadLocal`（如框架上下文，且在 `finally` 中严格清理）传递。

### 8.2 分层架构与模型边界隔离
- **Controller 层（薄层接入）**：
  - 职责仅限协议适配、请求校验与服务分发；
  - 必须使用 `jakarta.validation`（`@Valid` / `@Validated`）在入口完成参数校验；
  - **严禁编写复杂业务逻辑，严禁越级穿透直接调用持久层 Mapper/Repository**。
- **Service 层（核心编排）**：
  - 核心业务编排与事务边界控制；
  - 声明式事务 `@Transactional` 仅允许标注在 public 接口或 Service 方法上；
  - **严禁在 `@Transactional` 方法内执行耗时外部 HTTP / RPC 调用**，防止数据库连接被长时间占用耗尽连接池。
- **三层数据模型物理隔离**：
  - **入参模型**：`*DTO` / `*Command` / `*Query`（纯数据入参契约推荐使用 Java 17+ `record`，天然不可变）；
  - **出参模型**：`*VO` / `*Response`（面向调用方的视图对象）；
  - **持久模型**：`*PO` / `*Entity`（仅用于持久层与数据库表的映射映射）；
  - **红线底线**：**绝对禁止将底层持久化实体（Entity/PO）直接作为 Controller 接口出入参**，模型转换必须在 Service 或通过 MapStruct / 转换器显式完成。

### 8.3 统一响应契约与异常体系
- **统一响应包装**：
  - 所有对外 RESTful API 返回必须统一封装为结构化对象 `Result<T>`（包含 `code`、`message`、`data`、`timestamp`）；
- **全局异常兜底**：
  - 统一通过 `@RestControllerAdvice` 集中拦截异常并映射为业务错误码；
  - 自定义业务异常 `BusinessException` 须包含明确的状态码与对用户友好的报错信息；
  - 未捕获的未知异常在全局切面中记录受管 `log.error` 后，返回通用的“系统繁忙/未知错误”，**绝对严禁向前端外泄原始 SQL 语法错误、表结构或 Java 异常堆栈**。

### 8.4 现代 Java 21/17 语法与时间标准
- **时间日期全量 `java.time.*`**：
  - 统一使用 `Instant`（时间戳）、`LocalDateTime`（无时区时间）、`LocalDate`、`Duration` 等现代不可变类；
  - 序列化统一使用 ISO-8601 格式或项目标准格式（如 `yyyy-MM-dd HH:mm:ss`）；
- **拥抱现代语法特性**：
  - 只读数据传输载体优先使用 `record`；
  - 类型判断优先使用模式匹配（Pattern Matching for `instanceof` 与 `switch`）；
  - 集合不可变工厂优先使用 `List.of()`、`Set.of()`、`Map.of()`。

### 8.5 性能底线与持久层防御
- **N+1 查询彻底杜绝**：
  - 严禁在循环体内发起逐条数据库查询；批量数据检索必须使用 `IN` 条件或批量查询接口；
- **深分页防扫描**：
  - 分页接口强制限制最大 `pageSize`；大数据量深分页禁止使用大偏移量 `LIMIT offset, size`，必须基于主键/唯一索引游标或覆盖索引子查询优化；
- **Lombok 与 ORM 安全**：
  - 在 JPA/Hibernate 实体类上**严禁滥用 `@Data`**（其默认生成的 `equals` 与 `hashCode` 在双向关联下极易诱发无限递归导致 `StackOverflowError`）；
  - 推荐按需使用 `@Getter`、`@Setter`，重写 `toString` 时显式排除关联属性。

### 8.6 代差排斥清单 (Forbidden Legacy APIs)
- ❌ **绝对禁止使用 `javax.*` 命名空间**：必须使用 Spring Boot 3 对应的 `jakarta.*`（如 `jakarta.validation.*`、`jakarta.annotation.*`、`jakarta.servlet.*`、`jakarta.persistence.*`）；
- ❌ **绝对禁止使用 `java.util.Date` 与 `java.util.Calendar`**；
- ❌ **绝对禁止在私有属性上直接标注 `@Autowired`**；
- ❌ **绝对禁止使用 `System.out.println` 或 `e.printStackTrace()`**（统一使用 `@Slf4j` 日志门面）；
- ❌ **绝对禁止将持久化实体直接作为 Controller 接口出入参**。
